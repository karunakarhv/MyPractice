A **test case document** is a detailed document that outlines individual test scenarios for validating a specific feature or functionality of a software application. It provides step-by-step instructions for testers, ensures traceability, and facilitates repeatability of tests.

**Typical contents of a test case document include:**

---

### 1. Test Case ID
A unique identifier for the test case.

### 2. Test Case Name/Description
Brief, descriptive title or summary of what the test case covers.

### 3. Related Requirement(s)
References to requirement(s) or user story IDs that the test case validates.

### 4. Preconditions
Any setup or conditions that must be met before executing the test case (e.g., user logged in, specific data available).

### 5. Test Steps/Procedure
Ordered, detailed list of steps to perform the test. Each step specifies user actions and/or input data.

### 6. Test Data
Specific data values (inputs) needed for performing the test steps.

### 7. Expected Result(s)
The expected outcome after executing the test steps - what the system should do/show/output.

### 8. Actual Result(s)
The real result observed when the test is executed. (Usually filled in during test execution.)

### 9. Status/Result (Pass/Fail)
Indicates whether the test case passed or failed after execution.

### 10. Postconditions
The state of the system after the test is executed.

### 11. Priority/Severity
Risk level or importance of the test case.

### 12. Tested By
Name or ID of the person who performed the test.

### 13. Test Date
The date when the test case was executed.

### 14. Comments / Notes
Additional information, observations, or clarifications.

---

**In summary:**
A test case document ensures that testing is systematic, traceable, and reproducible. It provides all the necessary information for anyone to execute the test, check results, and record outcomes. Well-written test cases help ensure software quality and meet project requirements.
